# 故障实验室：六类典型 Agent 事故

::: tip 本课目标
故障注入用来检验系统，而不是证明设计一定正确。只在测试环境进行。
:::

## 1. 原理与边界

案例 A：429 + 重试风暴；B：外部写成功但响应丢失；C：慢 SSE 消费者导致 RSS 增长；D：上下文压缩丢失约束；E：检索 ACL 漏洞；F：租户独占 worker。每个案例均需症状、指标、假设、复现、修复与回归。

## 2. 贯穿项目中的例子

例如 A：模型限额降为原来的 50%，观察重试次数和 queue_wait；修复使用有界退避、全局预算与 admission。B 用稳定幂等键；C 限制缓冲并允许 seq 重放。

## 3. 动手实验

从六个案例中至少做三个：一个性能、一个可靠性、一个效果/安全。每次先记录未修复数据，再记录修复后数据和副作用；不得对生产系统注入故障。

先记录基线、环境和失败样本，再做控制变量实验。使用[实验模板](../../guide.md)保存结论。

## 4. 验收标准

至少三份事故复盘，含根因证据、修复对照、残余风险及预防回归测试。

## 5. 定向阅读

- [参考资料](https://sre.google/sre-book/postmortem-culture/)：无责复盘、可执行改进项。

将阅读内容映射到自己的系统，明确哪些机制可以复用、哪些需要验证。

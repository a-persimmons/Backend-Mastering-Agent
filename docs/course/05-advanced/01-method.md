# 独立问题求解：从现象到可验证结论

::: tip 本课目标
从教程驱动转向问题驱动，面对陌生故障先明确影响，再寻找证据。
:::

## 1. 原理与边界

流程：定义问题与成功标准 → 建立系统因果图 → 获取基线 → 排序假设 → 单变量实验 → 解释结果 → 选择最小可行修改 → 回归验证与回滚。相关性不等于因果。没有证据时要明确不确定性，避免过早重写。

## 2. 贯穿项目中的例子

症状：任务成功率下降、P99 增长。先按版本、租户、模型、工具、负载分层；若队列等待升高而模型延迟不变，优先验证调度；若 token 增长，检查 context 变化。

## 3. 动手实验

选择一个未知故障，让同伴或自己随机注入但暂时不看原因；按实验模板记录至少三个假设、排除证据和最小修复。

先记录基线、环境和失败样本，再做控制变量实验。使用[实验模板](../../guide.md)保存结论。

## 4. 验收标准

能从指标定位到模块、从模块定位到可检验假设；提交可复现步骤，而不是事后猜测。

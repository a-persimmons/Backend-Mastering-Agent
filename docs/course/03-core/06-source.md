# 源码研读：Codex、Eino 与 Java Agent

::: tip 本课目标
阅读成熟项目要围绕一个请求的生命周期，而不是逐文件浏览。
:::

## 1. 原理与边界

先固定 commit SHA，运行一个最小示例并记录日志。沿入口、模型适配器、状态/事件、工具调度、取消、权限和测试逐步定位。区分框架提供的机制与部署层承担的责任。对源码中没有证据的生产行为不作推断。

## 2. 贯穿项目中的例子

选 Codex Rust core 和 Eino Go ADK 各一个工具执行路径；或者用 Spring AI Alibaba 对照 Java 实现。用搜索定位 call_id、cancel、checkpoint 及相应测试。

## 3. 动手实验

输出两张调用链图和一份对照表：执行循环、错误策略、事件协议、状态持久化、测试覆盖、可替换边界。把一个设计移植到自己的 V0.3。

先建立可运行基线，保存输入、日志、版本与失败样本，再进行对照实验。输出记录可采用[实验模板](../../guide.md)。

## 4. 验收标准

能在源码中找到依据并给出文件路径与 commit；实现一个借鉴机制并证明行为改善。

## 5. 定向阅读

- [参考资料](https://github.com/cloudwego/eino)：ADK 与 compose、examples；结合 Codex 和 Spring AI Alibaba。

阅读后用自己的实现解释设计取舍，而不是抄写 API。

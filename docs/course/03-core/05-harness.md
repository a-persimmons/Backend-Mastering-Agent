# Harness：规划、执行、反馈和长任务

::: tip 本课目标
Harness 是围绕模型的控制系统，负责使任务可持续、可验证、可停止。
:::

## 1. 原理与边界

将目标分解为可检验任务，记录 plan、进度和证据。模型可生成计划但完成条件由测试、业务约束或人类确认。失败反馈需要可操作信息；限制重复尝试、预算与运行时间。对跨上下文任务保留工作日志和可恢复状态。

## 2. 贯穿项目中的例子

工单长任务有检查清单：确认服务状态、找证据、给建议、人工批准写操作、确认写入。每项有 expected evidence；不能只凭模型说“完成”。

## 3. 动手实验

在任务第 3 步注入失败与上下文重置。比较无进度记录和持久化计划+验证的完成率、重复步骤和 token。设计人工接管条件。

先建立可运行基线，保存输入、日志、版本与失败样本，再进行对照实验。输出记录可采用[实验模板](../../guide.md)。

## 4. 验收标准

实现有限重规划、明确完成判定和预算耗尽路径；提供失败轨迹及恢复证据。

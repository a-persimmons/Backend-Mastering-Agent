# Context 与 Memory：应用层最小设计

::: tip 本课目标
Context 是本轮送给模型的信息；Memory 是可跨轮次复用的信息存储。两者都不是 KV Cache。
:::

## 1. 原理与边界

区分系统规则、当前请求、近期历史、检索证据、工具结果。为每类分配预算并保留消息边界。会话历史按 session 存储，长期事实须有来源和更新机制。历史与检索证据不应覆盖更高优先级规则。

## 2. 贯穿项目中的例子

工单 Agent 保留最近 6 条消息、当前工单状态和最多 3 个相关知识片段；旧日志存对象存储，仅注入摘要或引用。对包含密钥的信息脱敏。

## 3. 动手实验

构造 30 轮对话，在第 3 轮提供关键信息，第 25 轮更正。对比全历史、滑动窗口、摘要+检索的正确率与 token。

先建立可运行基线，保存输入、日志、版本与失败样本，再进行对照实验。输出记录可采用[实验模板](../../guide.md)。

## 4. 验收标准

能说明上下文窗口、会话和记忆的不同生命周期，并给出可复现的 token 预算策略。

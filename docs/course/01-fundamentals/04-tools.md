# 工具调用协议：模型提议，程序执行

::: tip 本课目标
Tool Calling 由模型提出调用意图，真正的执行、校验、鉴权都由程序控制。
:::

## 1. 原理与边界

定义工具名、描述、输入 schema 和输出约定。处理 call_id 与工具结果的关联；工具错误是状态，不一定是异常。外部数据可能含提示注入，不能将工具结果当高优先级指令。副作用工具需要幂等、审批、租户校验。

## 2. 贯穿项目中的例子

get_service_status(service) 为只读；create_ticket(title, idempotency_key) 为写操作。模型不能自行声明已审批。服务端根据用户身份和授权策略决定执行，不能信任模型生成的 tenant_id。

## 3. 动手实验

给模拟工具传入未知工具名、错误类型、超长参数、越权租户、超时及重复调用。观察 dispatcher 输出的稳定错误类型。

先建立可运行基线，保存输入、日志、版本与失败样本，再进行对照实验。输出记录可采用[实验模板](../../guide.md)。

## 4. 验收标准

实现工具注册表和参数校验；证明不合法或未授权的调用不会触发副作用。
